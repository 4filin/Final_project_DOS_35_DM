# Часть 2. Автоматизация: CI/CD пайплайн (GitHub Actions)


Настраиваю автоматику в GitHub: теперь при каждом `git push` система сама
проверяет код, собирает его, гоняет тесты и сообщает результат в Telegram.
При пуше в основную ветку (`master`) дополнительно происходит деплой —
выкладка приложения на сервер.


Всё описывается в одном файле `.github/workflows/ci-cd.yaml`  GitHub выполняет на своих виртуальных машинах (раннерах).

## Пайплайн (три job'а)

| Job | Когда запускается | Что делает |
|---|---|---|
| `build-and-test` | при любом пуше в любую ветку | 1) проверяет код линтером → 2) собирает → 3) гоняет тесты → 4) пробует собрать Docker-образ |
| `deploy` | **только** при пуше в `master` | собирает образ → отправляет его в хранилище образов (ECR, см. часть 3) → выкладывает в кластер EKS|
| `notify` | всегда, в любом исходе | отправляет сообщение в Telegram: ветка, коммит, результат каждого job'а |

Связь между ними: `deploy` ждёт успешного `build-and-test` (`needs:`) — нельзя
за деплоить то, что не собралось. Условие `if: github.ref == 'refs/heads/master'`
у job'а `deploy` означает: на других ветках деплой пропускается.

## Cценарий одного цикла

```
Коммит и пушь
        │
        ▼
GitHub Actions берёт чистую виртуальную машину
        │
        ▼
build-and-test: линтер ✅ → build ✅ → тесты ✅ → docker build ✅
        │
        ├── пуш был в develop → deploy пропущен → Telegram: «Сборка: success, Деплой: skipped»
        │
        └── пуш был в master → deploy: образ в ECR → kubectl apply → новая версия 
                                 → Telegram: «Деплой: success»
```

## Версия образа = SHA коммита

Каждый образ помечается двумя тегами: `latest` и хешем коммита (например,
`:a1b2c3d`). Деплой указывает кластеру **точный хеш**. Если указывать только
`latest`, кластер не понимает, что образ обновился, и продолжает работать на старом.
С хешем любая версия однозначно привязана к коммиту  и легко откатиться .

## Зависимости этапа

- **Вход**: код и Dockerfile из шаг 1.
- **Внешние зависимости**: секреты в настройках репозитория (Settings → Secrets):
  ключи AWS, токен Telegram, SSH-ключ. Без них job'ы не смогут подключиться
  к облаку.
- **Выход**: проверенный код + образ в ECR + (для master) приложение в кластере.
