# Часть 3. Инфраструктура из кода: Terraform и Ansible


Описывю всё оборудование в облаке AWS текстовыми файлами. После этого любой
стенд можно поднять одной командой — точно такой же, как был, без ручных кликов
в консоли. Hастройка операционной системы на серверах занимается Ansible.


## Terraform: что создаю (папка `terraform/`)

| Файл | Что создаёт |
|---|---|
| `provider.tf` | Подключение к AWS (регион us-west-1) и **backend** — где Terraform хранит свою «память» (state). Память лежит в S3-бакете `dos35-md-final-project-study` (с шифрованием) |
| `ecr.tf` | Реестр образов — «склад» Docker-образов, куда CI их складывает |
| `ec2.tf` | Виртуальный сервер (машина) для мониторинга + правила firewall (какие порты открыты: 22, 80, 9090, 3000) |
| `eks.tf` | Kubernetes-кластер (шаг 5) |
| `elk.tf` | Второй сервер под систему логирования в другом регионе (us-west-2) + своя сеть для него |

**Про state и бакет.** Terraform помнит, что он создал, в файле state. Чтобы
несколько человек могли работать вместе, state хранится в облаке (S3), а не на
ноутбуке. Бакет для state нельзя создать самим Terraform'ом бакет создаётся
один раз вручную:

```bash
aws s3 mb s3://dos35-md-final-project-study --region us-west-1
```

## Ansible: что настраиваем (папка `ansible/`)

Плейбук `playbook.yml` разбит на три play'я:

1. **На все серверы** — установить Docker и плагин docker compose.
2. **Сервер мониторинга** — установить nginx (входная точка для пользователей,
   см. часть 5) и поднять контейнеры Prometheus/Grafana (шаг 4).
3. **Сервер логирования** — поднять контейнеры Elasticsearch/Kibana (шаг 6).

**Как Ansible узнаёт адреса серверов.** Есть два списка машин (inventory):
- `aws_ec2.yml` — **динамический**: при запуске Ansible сам спрашивает у AWS:
  «дай все машины с тегом Name=final-project-app» и берёт их IP из ответа.
  Машину пересоздали — адрес сменился — Ansible всё равно её найдёт.
- `elk_static.yml` — **статический**: просто список с IP лог-сервера (он живёт
  в другом регионе, динамический поиск его не видит).

Общие настройки подключения (логин, SSH-ключ) лежат в `group_vars/all.yaml`.

## Как это работает (по шагам)

```
terraform init     — скачать плагины AWS, подключиться к бакету state
terraform plan     — показать, ЧТО будет создано (ничего не создаёт)
terraform apply    — создать
        │
        ▼
ansible-playbook -i ansible/aws_ec2.yml -i ansible/elk_static.yml ansible/playbook.yml
                   — зайти на каждый сервер и настроить его
```

## Зависимости этапа

- **Вход**: аккаунт AWS, созданный вручную S3-бакет, SSH-ключ (`~/.ssh/final_project`).
- **Выход**: работающие серверы с установленными программами. Ждут деплоя
  приложения из шага 2 и подключения кластера из шага 5.
- **Полный цикл восстановления с нуля**: `terraform apply` → `ansible-playbook`
 → `aws eks update-kubeconfig` → `git push` (CI доставит приложение).

## Где что лежит

```
terraform/   — .tf файлы (описание оборудования)
ansible/     — playbook.yml, aws_ec2.yml (динам. список), elk_static.yml (статич.),
               group_vars/all.yaml (логин/ключ), ansible.cfg
```
