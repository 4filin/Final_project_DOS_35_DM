# Часть 6. Централизованное логирование: Filebeat + Elasticsearch + Kibana

Собираем **все логи всех контейнеров** кластера в одно хранилище, где их можно
искать и фильтровать в веб-интерфейсе. 

## Из чего состоит система (стек Elastic)

| Компонент | Роль  | Где живёт |
|---|---|---|
| Filebeat | Курьер: на каждой машине кластера читает файлы логов контейнеров и отправляет в хранилище. Попутно приклеивает к каждой записи метки Kubernetes (имя пода, машины, образ) | под кластера (DaemonSet) |
| Elasticsearch | Хранилище и поисковик: принимает логи, индексирует, отвечает на поисковые запросы за миллисекунды | отдельный сервер, порт 9200 |
| Kibana | Веб-интерфейс: страница поиска (Discover), фильтры, просмотр документов | тот же сервер, порт 5601 |

## Cхема

```
Под приложения пишет лог (fmt/log в Go → stdout)
        │
        ▼
/var/log/containers/*.log на машине кластера
        │
        ▼
Filebeat (по одному на каждой машине, описан в k8s/filebeat.yaml)
   читает файлы + добавляет метки: kubernetes.pod.name, node, image...
        │  отправляет по HTTP
        ▼
Elasticsearch (сервер логирования, отдельная машина)
        ▲
        │
   Kibana — интерактивный кластер
```

**Почему отдельная машина под логи.** Хранилище Elasticsearch требовательно к
памяти и не должно конкурировать за ресурсы с мониторингом — поэтому это третий
сервер проекта. Отдельно: он находится в **другом регионе AWS** (us-west-2), так
как в основном регионе исчерпана стартовая квота на процессоры нового аккаунта.
Квоты в AWS считаются по регионам — это легальный обход, с заявкой на повышение
квоты в поддержку.

**Почему без Logstash.** Filebeat умеет и собирать, и размечать, и отправлять —
промежуточный компонент здесь не нужен.

## Как это работает (по шагам)

1. Kubernetes пишет всё, что программы выводят в консоль (stdout/stderr), в файлы
   на диске машины.
2. Filebeat (DaemonSet = «по одной копии на каждой машине») читает эти файлы.
3. Каждая запись обогащается метаданными: имя пода, машины, образа.
4. Записи отправляются в Elasticsearch, который раскладывает их по индексам
   (по дням).
5. В Kibana создаётся «представление данных» (Data View `filebeat-*`) — и можно
   искать: например, `kubernetes.pod.name : "final-golang*"` покажет только
   логи приложения.

## Что видит человек в Kibana

Каждая строка лога — документ с полями: само сообщение (`GET / 2.5µs`), имя пода,
машина, **образ с хешем коммита**. Это даёт сквозную цепочку: коммит в git →
образ → под → метрика в Grafana → лог в Kibana.

## Проверка работы

```bash
kubectl -n kube-system get pods -l app=filebeat -o wide   # по поду на каждой машине
curl http://<IP_лог_сервера>:9200/_cat/indices?v          # индексы filebeat-* растут
```
Затем в браузере: `http://<IP_лог_сервера>:5601` → Data View `filebeat-*` →
Discover → поиск по логам подов приложения.

## Зависимости этапа

- **Вход**: работающее приложение в кластере (шаг 5), сервер логирования
  (шаг 3, файл `terraform/elk.tf`), Ansible (play 3) для установки стека.
- **Выход**: веб-поиск по всем логам кластера.

## Где что лежит

```
k8s/filebeat.yaml                    — DaemonSet + настройки отправки в ES
terraform/elk.tf                     — сервер логирования и его сеть (us-west-2)
monitoring/docker-compose.elk.yml    — контейнеры elasticsearch + kibana
ansible/elk_static.yml               — адрес лог-сервера для Ansible
```
