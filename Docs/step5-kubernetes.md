# Часть 5. Kubernetes (EKS): где живёт приложение и как до него достучаться


Переводим приложение с «одного сервера с Docker» в **Kubernetes** — систему,
которая сама следит за приложением: запускает несколько копий, распределяет
нагрузку, перезапускает упавшее. AWS-версия Kubernetes  **EKS**.

## Что такое Kubernetes простыми словами

- **Кластер** — группа машин, на которых крутится приложение.
- **Под** — минимальная единица: один запущенный экземпляр приложения (у нас
  всегда 2 пода — запасной на случай падения).
- **Deployment** — описание «каким должно быть приложение»: образ, число подов,
  правила проверки здоровья.
- **Service** — стабильная «точка входа» с постоянным адресом, которая
  распределяет трафик между подами.
- **NodePort** — тип Service, который открывает порт на **всех** машинах кластера.

## Кто управляет

В Kubernetes есть управляющие узл (мастера) и рабочие (ноды). В EKS мастера —
это ответственность AWS (они невидимы, отказоустойчивы, входят в цену сервиса).
Мы управляем только рабочими нодами: в нашей группе 2 машины (можно расширить
до 3), Kubernetes сам распределяет поды по ним.

## Запуск приложения (папка `k8s/`)

| Файл | Что описывает |
|---|---|
| `deployment.yaml` | Приложение: 2 копии; проверки здоровья (readiness `/readyz` — «готов ли принимать трафик», liveness `/healthz` — «не завис ли»); образ указывается по тегу коммита (см. ниже) |
| `service.yaml` | Входная точка: NodePort **30080** → перенаправляет на порт 8080 подов |

## Связь с шагом 2

1. CI собирает образ и загружает его в ECR (склад образов, шаг 3).
2. CI командой `kubectl apply -f k8s/` передаёт кластеру наши описания.
3. `kubectl set image` используем образ с тегом = хешем этого коммита.
4. Kubernetes скачивает образ из ECR (IAM роли) и перезапускает поды по одному — **сайт не прерывается**.
5. Пока поды не ответят «готов» на `/readyz`, трафик им не идёт.

## Путь запроса

```
Браузер ──► nginx (сервер мониторинга, порт 80)
                │  nginx сам выбирает, на какую машину кластера отправить
                ▼
            машина кластера :30080  (NodePort есть на каждой ноде)
                │
                ▼
            Service ──► один из подов приложения :8080
```


## Проверка работы

```bash
kubectl get pods -o wide        # 2 пода, на разных машинах
kubectl get nodes -o wide       # 2 машины кластера
curl http://<IP_сервера>/       # приложение отвечает через nginx
```
**Проверка балансировка**
`kubectl logs -l app=final-golang -f --prefix` — при
нескольких обращениях видно, как запросы по очереди обрабатывают разные поды:


## Зависимости этапа

- **Вход**: образ приложения в ECR (шаг 1+2), кластер и сервер nginx (шаг 3),
  CI для доставки (часть 2).
- **Выход**: работающее приложение с распределением нагрузки — источник метрик
  (шаг 4) и логи (шаг 6).

## Где что лежит

```
k8s/deployment.yaml   — приложение: поды, проверки здоровья
k8s/service.yaml      — входная точка (NodePort)
terraform/eks.tf      — описание самого кластера
```
